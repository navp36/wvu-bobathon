    How it protects student information

    This prototype collects nothing.
    • Everything runs in your browser. No server, no network calls, no analytics.
    • Your selections are not saved: reload and they are gone (no cookies, no localStorage).
    • The catalog is fictional. No real student records are used.
    • A production version would need single sign-on, read-only scoped access, and no storage of grades or IDs outside the registrar's systems.

    System Architecture & Data Flow

    1 · Presentation & State

    Pure client-side DOM rendering with reactive state for completed courses (Set) and registered section IDs (Array). Zero external framework dependencies.

    2 · Feasibility Engine

    In-memory multi-constraint solver evaluating prerequisites, time-interval overlaps, and physical campus transit gaps (PRT/shuttle travel times).

    3 · Production Target

    Architected for frictionless evolution to campus SSO (Shibboleth/SAML), Banner SIS APIs for real-time seat polling, and Degree Works audit integration.

    # Smart Class Registration Architecture Summary
- Pattern: Ephemeral Client-Side Reactive Single-Page Application (SPA)
- Rendering: Vanilla JS with DOM replacement (replaceChildren)
- Constraints Checked:
  1. Prerequisite verification against selected completed courses
  2. Same-day interval collision detection: max(start_A, start_B) < min(end_A, end_B)
  3. Inter-campus transit gap check: start_second - end_first >= TRAVEL[campus_A][campus_B]
- Data Privacy: Zero persistence (no localStorage, no cookies, no tracking)
